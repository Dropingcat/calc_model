# TD-2177-004 — Жёсткий запрет экстраполяции T(V) (ГОСТ 2177-99, п. 5.5.8)

**Статус:** закрыт в `fraction_lib` (код + тесты). Книга v3.12 синхронизация — отдельный долг TD-2177-001.
**Реализация:** `GOST2177Calculator._check_extrapolation` (хук `_check_extrapolation` добавлен в `BaseDistillationCalculator.calculate`, вызывается сразу после `_fill_missing`).
**Константа политики:** `GOST2177_EXTRAPOLATION_MAX_PCT = 95.0` (`fraction_lib/constants.py`).
**Исключение:** `InvalidTestError(code="EXTRAPOLATION_FORBIDDEN")` (`fraction_lib/exceptions.py`).
**Флаг:** `EXTRAPOLATED_96_98` — легализованная экстраполяция точек 96–98%.

## Нормативное основание

ГОСТ 2177-99 (с Изм. №1) п. 5.5.8: значения температуры при определённом проценте отгона
определяют **только интерполяцией между наблюдёнными точками**; экстраполяция кривой
T(V) за диапазон фактических наблюдений **запрещена**. Если требуемая точка не может быть
получена интерполяцией — испытание считается проведённым неполно, результат не выдаётся.

## Принятая политика расчётного слоя

| Ситуация | Решение | Механизм |
|---|---|---|
| Точка ≤ 95% наблюдалась | ок | — |
| Точка ≤ 95% внутри диапазона наблюдений (≥2 наблюдённых точек) | ок — это линейная **интерполяция**, не экстраполяция | разрешено молча |
| Точка ≤ 95% вне диапазона наблюдений (левее первой / правее последней наблюдённой) | **FAIL** | `InvalidTestError("EXTRAPOLATION_FORBIDDEN")` |
| Точки 96–98% без наблюдения | ok с предупреждением — легализованная линейная экстраполяция по крайним наблюдённым точкам | флаг `EXTRAPOLATED_96_98` |
| FBP/КК (100%) без наблюдения | **FAIL** (> 98%) | `InvalidTestError` |
| IBP/НК (0%) без наблюдения | **FAIL** (вне диапазона наблюдений) | `InvalidTestError` |

### Обоснование исключения 96–98%

Ветка нормирования «потери ≥ 2%» (п. 5.5.6/5.5.9) требует значения 96%-й точки даже тогда,
когда наблюдение обрывается на 95%-й. Полный отказ здесь сделал бы невозможным расчёт
скорректированных потерь Vk = A·L + B для легитимных проб. Поэтому экстраполяция
ограничена узким коридором 96–98%, выполняется строго линейно по двум крайним
наблюдённым точкам и **обязательно помечается флагом** — потребитель результата (книга,
отчёт, SOP) обязан отобразить его как ограничение результата. Всё, что выходит за
коридор (КК/FBP), запрещено безусловно.

## Контракт API

* `FractionResult.Flags` содержит `"EXTRAPOLATED_96_98"`, если хотя бы одна точка 96–98% получена расчётом.
* При запрещённой экстраполяции `calculate()` бросает `InvalidTestError`; в `.details`:
  `point`, `volume_pct`, `policy_max_pct`, `observed_range`.
* Хук по умолчанию в базовом классе — no-op (ASTM D86/ISO 3405 политику ГОСТ не наследуют;
  у D86 собственные ограничения оговорены в TD-D86-00x).

## Тесты (`fraction_lib/tests/test_gost2177.py::TestExtrapolationBanTD2177004`)

1. `test_interpolation_below_95_allowed` — разреженная кривая 20/50/90: интерполяция ок, флагов нет.
2. `test_extrapolated_96_allowed_with_flag` — 96% без наблюдения → флаг `EXTRAPOLATED_96_98`.
3. `test_extrapolation_beyond_98_forbidden` — FBP без наблюдения → `EXTRAPOLATION_FORBIDDEN`.
4. `test_point_left_of_first_observed_forbidden` — IBP без наблюдения → `EXTRAPOLATION_FORBIDDEN`.
5. `test_fully_observed_curve_no_flags` — полная кривая → ошибок и флагов нет.
