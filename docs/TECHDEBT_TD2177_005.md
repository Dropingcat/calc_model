# TD-2177-005 — Раздельные решения по сходимости и воспроизводимости

**Статус:** закрыто в расчётном слое fraction_lib (2026-10-08).
**Нормативная база:** ГОСТ 2177-99, п. 6.4 (нормы точности: сходимость r,
воспроизводимость R), метод А (номограмма рис. 6) / метод Б (табличные значения).

## Суть долга
Ранее критерий повторяемости (|X1−X2| ≤ r) был единственным живым решением;
значения R присутствовали в Metrics только как число (и K/R_ok). Не было
формализованного ОТДЕЛЬНОГО решения для сравнения двух результатов из разных
условий (лаборатории, исполнители, дни). Смешение этих процедур — типичная
ошибка эксплуатации: нарушение R ошибочно трактуется как «испытание
недействительно», хотя по смыслу стандарта оно делает несовместимым именно
*сравнение*.

## Реализация (раздельность закреплена кодом)
1. **Сходимость (r)** — остаётся ВНУТРИ расчёта серии: пары определений
   `T_obs={pct:[x1,x2]}` → `RepeatabilityViolation` при |X1−X2| > r
   (`GOST2177Calculator._check_repeatability`). Результат серии блокируется.
2. **Воспроизводимость (R)** — новый decision-слой
   `GOST2177Calculator.compare_results(res1, res2, strict_R=False)`:
   - по каждой общей точке: diff = |X̄1 − X̄2|, норма R берётся из Metrics.R
     результата (метод А — номограмма по крутизне книги-расчёта);
   - вердикт `COMPATIBLE` / `REPRODUCIBILITY_EXCEEDED` + перечень нарушений
     `{point, x1, x2, diff, R}` — отдельные результаты при этом НЕ отменяются;
   - `strict_R=True` — режим приёмки: выбрасывается
     `ReproducibilityViolation` (code REPRODUCIBILITY_VIOLATION,
     details.severity="decision") на первой нарушенной точке.
3. Класс исключения добавлен в `fraction_lib.exceptions` и экспорт `__all__`.

## Границы применения (для SOP)
- compare_results сравнивает скорректированные T_corr; вход — два полных
  результата calculate() на одном наборе точек; отсутствующие общие точки
  пропускаются (в checked не попадают).
- Нарушение R ≠ брак испытаний каждого из результатов; решение о повторе/
  аккредитации принимает метролог по протоколу. Для автоматической приёмки
  используйте strict_R=True.

## Тесты
`TestSeparateConvergenceReproducibilityTD2177005` (5 шт., всего 227 passed):
r≠R не смешиваются; diff>r но ≤R → COMPATIBLE? нет — вердикт EXCEEDED только
при diff>R (проверено на числах S=0: r=3.0, R=6.4); совместимая пара;
strict_R бросает исключение с severity=decision; внутрирасчётная проверка
повторяемости сохранена без изменений.
