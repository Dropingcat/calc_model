## 1. Производительность и устойчивость формул

| Показатель | ГОСТ 2177 | ГОСТ ISO 3405 (×2) | ASTM D86 | ASTM D1160 |
|---|---|---|---|---|
| Формул | 532 | 866 | 871 | 260 |
| Макс. длина формулы | **782** ⚠️ | 215 | 214 | 190 |
| Волатильные ф-ции (RAND/NOW/OFFSET...) | 0 | 0 | 0 | 0 |
| Массивные формулы | 0 | 0 | 0 | 0 |
| Диапазоны >500 строк | 0 | 0 | 0 | 0 |
| Глубокие IF (>4) | 0 | 1 (J36: IF×11) | 1 (K36: IF×11) | 0 |
| Битые ссылки | 0 | 0 | 0 | 0 |

### Находки
1. **Длинные формулы (782 символа)** — ГОСТ 2177: интерполяция A/B таблицы 4 (H28) — монстр из INDEX/MATCH. Не ошибка, но трудносопровождаемо (см. ФР-20: перенос в Python).
2. **Глубокие IF×11** — D86 `расчёт!K36`, ISO `Лист1!J36`: блок «температуры → крутизна» с 11 вложенными IF (определение соседней непустой точки). Это «тихая смерть»: при сдвиге строки формула не упадёт, а выдаст неверный результат. **Рекомендация:** заменить на ИНДЕКС+ПОИСКПОЗ по непустым значениям или Python.
3. **Связки листов корректны**: «Вывод»→«Ввод данных», «расчёт»→«ввод данных» — однонаправленные, кольцевых зависимостей НЕТ (проверено).
4. **D47–D51 в D86/ISO** — НЕ битые: это блок «Скорректированная температура» (`=расчёт!E42–E46`, `='Группы 1-4'!D38<750 ? + : −`). Семантика упрощена (знак поправки по порогу 750 мм вместо полной формулы Янга `0.00012·(760−P)·(273+t)`) — см. ФР-23.

## 2. Критичный дефект, переносимый из библиотеки в Excel (ФР-23)

**Краш-тесты (`test_pressure_crash.py`) нашли:** формула коррекции потерь ISO 3405 / D86
`Lc = 0,5 + (L−0,5)/(1+0,125·(101,3−p))` имеет **полюс при p = 109,3 кПа (~820 мм рт.ст.)**:
- P=819.82 мм, L=0.3 → знаменатель ≈ 1e-16 → **Loss = 38059 %** (астрономия);
- P=800 мм → Loss = **−0.106 %** (отрицательные потери, физически абсурдно).

**В Excel-книгах (Лист1!H28/G26, расчёт!L28) эта формула есть без защиты** → при вводе P>797 мм лаборант получит мусор (отрицательные потери или #DIV/0!).

**Исправление в Excel:** добавить условие `IF(p_кПа > 101.3, L, формула)` (при P>760 мм — потери не корректировать) во все ячейки коррекции потерь:
- `ГОСТ ISO 3405…` Лист1: строки коррекции потерь (J, K);
- `АСТМ Д 86-1-4…` расчёт: строки коррекции (M, N);
- `фракционка ГОСТ_2177…` — НЕ трогать (там таблица 4, диапазон [560,760] уже ограничен).

**Статус:** 🔴 ФР-23 (критический, перенести из библиотеки).

## 3. Ревью UX (дружелюбность интерфейса)

### Проблемы (ФР-18…ФР-22 уже в реестре, здесь — новые/уточнённые)

**ФР-24 — Упрощённое правило поправки давления (ISO/D86)**
- Формулы `IF(давление<750, +поправка, −поправка)` вместо полной формулы Янга `0.00012·(760−P)·(273+t)`.
- При P=748: полная формула даёт +0.00012·12·(273+t) ≈ +0.7°C при 300°C; упрощённая — ту же величину, но **знак фиксирован по порогу**, а не по величине (P=740 и P=800 оба дают «−» при 800 — но при 800 формула Янга даёт −, т.е. ок; при 740 даёт +, ок). По сути работает, но при P близко к 750 (например 749) пороговая логика может дать знак, отличный от непрерывной формулы на ±. **Рекомендация:** заменить порог 750 на полную формулу (единообразие с ГОСТ/библиотекой).

**ФР-25 — Ввод двух определений (X1, X2) без явного контроля повторяемости**
- Книги принимают 2 определения, но критерий `|X1−X2| ≤ r` (RepeatabilityViolation в библиотеке) в Excel НЕ реализован явно: колонка |X2−X1| есть, но нет авто-пометки «превышение r» (красным/флагом).
- **Рекомендация:** условное форматирование: если |X2−X1| > r → ячейка красная + текст «повторить определение».

**ФР-26 — Нет валидации ввода (диапазоны)**
- Нет ограничений ввода: давление может быть 9999, температура 9999, потери отрицательные.
- **Рекомендация:** Data Validation: давление 560–800 (или 101.3±), потери 0–5, температура 0–500; подсказки при вводе.

**ФР-27 — Нет листа «О книге» / инструкции (ISO 17025)**
- Подтверждено: нет версии, даты, ФИО, ссылки на стандарт/редакцию. Для лаборатории критично (прослеживаемость).
- **Рекомендация:** лист «О книге»: версия, дата, стандарт+редакция, метод, автор/проверил/утвердил, ссылка на свидетельство ГСО (для K).

**ФР-28 — Разнобой терминологии и опечатки**
- «Обем»→«Объём», «Потерм»→«Потери», «Ведите»→«Введите», «Скоррктированная»→«Скорректированная», «Расчитанные»→«Рассчитанные», «Округл+скор проц отгона и потерь» — неоднозначно.
- **Рекомендация:** единая терминология, вычитка.

**ФР-29 — Цветовое кодирование результатов отсутствует**
- Нет цветовой маркировки: SUPPORTED/не прошло, «для ГСО»/«для ОК» совпало/не совпало.
- **Рекомендация:** условное форматирование: результат ≤ K → зелёный, > K → красный (критерий из свидетельства ГСО).

**ФР-30 — Мусорные листы и дубликаты**
- `АСТМ Д 86` «Лист2» (несвязанные данные 187/188...), `ГОСТ ISO 3405` «Лист2/Лист3» (тестовые), дубликат `ГОСТ ИСО 3405… .xlsx`.
- **Рекомендация:** удалить/переименовать/задокументировать; оставить один канонический ISO-файл.

**ФР-31 — Блок «температуры → % выпаривания» (D86/ISO) перегружен**
- Строки 36–52: 11 вложенных IF (см. п.1), семантика C41=«Введите температуры» неоднозначна (была путаница 250/350 vs 47/95).
- **Рекомендация:** упростить: отдельный лист «ввод» (только данные) → расчёт → «вывод» (только результаты), разделить ввод и вычисления.
